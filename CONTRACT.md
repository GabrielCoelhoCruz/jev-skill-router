# Routing contract before implementation

Request: one nonempty natural-language string; never an instruction granting execution authority.
Skill: a unique stable `id`, nonempty `description`, and a nonempty list of short `examples` of applicable requests. The catalogue is data, not executable instructions.
Decision: exactly one of `route` with a catalogued `skill_id`, `no_skill` with null id, `review` with null id, or CLI `invalid` with null id and exit 2 for rejected input. `probabilities` maps every considered option (skill ids plus `__no_skill__` and `__review__`) to P in [0,1], summing to approximately 1; invalid and failed remote decisions have an empty map and null confidence. `confidence` is a separate [0,1] concentration value, not correctness. Missing credentials, transport failure, unsupported response model or invalid remote schema produce `review`, never a confident lexical route. `source` identifies jev, lexical, api or validation. `reason` names the boundary or policy decision. `usage` contains attempted calls, known input/output token counts or null if unknown, and input-only estimated USD or null if unknown. Dry-run alone uses the network-free lexical baseline. A case has `id`, `request`, `expected` (skill id or no_skill/review); evaluation checks exact outcomes, wrong routes, unnecessary reviews, route coverage, invalid/API failures, cost and latency. Labels and evaluation metadata are never included in model requests.
Jev distributions within 0.02 of unit mass are normalized for the returned decision; larger errors remain invalid. A measured run can retain original provider distributions in a sanitized audit outside the repository.

Evaluation protocol: exact correct action means predicted label equals expected label, including justified model review; an API or credential failure is never scored as a correct review. Wrong route means predicted skill ID differs from expected; unnecessary review means a valid predicted review on a case expected to route or answer without a skill. Automatic-route coverage divides predicted skill routes by all cases, and route recall divides correctly selected skill routes by expected skill-route cases. The grader requires the planned `(case id, repeat)` inventory and rejects missing, duplicate, or unexpected outcomes; its JSON report records every planned key and the case, repeat, and observation counts. Report all counts and denominators. Count API attempts, invalid remote responses and transport failures separately. Sum known token usage while marking unknown usage and incomplete cost; never replace unknown usage with zero in a total. Latency is observed wall time, not model-only latency. Record source SHA, pinned model, catalogue/config/dataset hashes, per-case predictions, confusion, and settings. The exact-match grader is deterministic on stored outcomes and must pass known correct, wrong, all-review, empty, invalid, and omitted cases twice. Comparative runs must use identical inputs and independent attempts, with no response reused between repeats. Report per-case action variability and family-cluster counts; repetitions of one case are not independent samples. The default is no cache and no retries. A separately authored final set must not be used for prompt tuning. This branch preserves the original provider prompt and makes no claim of improved semantic routing.
