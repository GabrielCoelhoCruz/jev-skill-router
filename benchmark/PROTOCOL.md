# Published-main measurement protocol

Frozen before the first live call on 2026-10-03 UTC. The done condition is a pinned published-main CLI check, an exactly inventoried 120-case dataset and three live repeats, six separate ordinary-answer controls, an offline lexical comparison and replay, honest failure accounting, and a clean isolated branch with offline checks. It does not require a target accuracy or a production-readiness claim.

- Known, previously used owner-written synthetic dataset `test-120.jsonl` SHA-256 `a1fd9b23e3ee2af166b25a15ea41f8163c8717c9bfa638b5ab2acb531e11f2ad`; `metadata.json` SHA-256 `f11a293ba5801a4365f8ad8e81faf611f89643226bd1a0c87c60e7e36a2c1302`. It is not fresh heldout or real traffic. Keep all labels and bytes intact. The inventory must be 120 unique IDs and 60 paired families, 96 skill labels and 24 review labels, with 60 English and 60 Portuguese cases.
- Primary plan: in dataset order, repetition 1 then 2 then 3; concurrency 1; model `jev-1.13.0`; one API attempt per planned pair; no retry, cache, or replacement. Exactly 360 observations planned. Record each decision, usage, reason, and wall latency. An incomplete plan is inconclusive rather than a smaller complete run. Expected labels, metadata, and rationales must never enter the HTTP request.
- Offline comparator: the published `lexical` function, on the same 120 requests once. Its word overlap is deliberately weak, not the best free baseline.
- Exact action includes `review` only when a valid model decision matches its label. Operational failures are incorrect even on review labels. Wrong skill route means a skill ID prediction different from the expected skill. Unnecessary valid review means expected skill or `no_skill`. Report numerator and denominator for skill selection, coverage, failures, and ordinary controls. Report each repeat and variability by 60 families. A fixed-seed family resampling interval describes only this synthetic set's variability. Latency P50/P95 are observed wall times; cost is input-only at the source's published rate if returned usage is complete, not an invoice.
- Ordinary-answer controls, all expected `no_skill`, are authored before calls and are NOT part of 120-case headline: `ordinary-01` `What is 2 + 2?`; `ordinary-02` `Olá, tudo bem?`; `ordinary-03` `Explain photosynthesis in one sentence.`; `ordinary-04` `Qual é a capital do Brasil?`; `ordinary-05` `Rewrite this sentence politely: I am late.`; `ordinary-06` `Traduza 'good morning' para português.`. Make six separate single-call observations. Do not tune from these outcomes.
- Local checks before live use: tests, route help, no-key and dry-run CLI, transport/truncation/timeout/schema tests, inventory and no-label-leak checks. Confirm configuration validation with custom catalogue and examples. Only fix reproducible operational defects, at most two small cycles, never modify provider prompt, options, model, thresholds, corpus labels, or selectively rerun live cases. If the runtime changes, separate new candidate from measured main.
- Publish owner-original corpus and sanitized observations only with offline verification. Never persist a key, Authorization header, or raw HTTP body. No other private data or providers.
